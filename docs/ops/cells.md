# Cells as code (OPS-052)

Hosting is **not decided** (DEC-04, `docs/adr/0016-hosting.md`). The code below is one option (AWS) behind a provider-neutral module.

| Path | What |
|---|---|
| `infra/terraform/modules/cell` | Provider-neutral contract: inputs, tags (`cell`, `service`, `country`, `environment` + per-resource `data_class`), residency allow-list (`residency.tf`), outputs |
| `infra/terraform/modules/cell/aws` | AWS implementation: private VPC (no internet gateway), Multi-AZ private Postgres 16, versioned KMS-encrypted buckets (audit archive with object lock), KMS root key per data class (`phi`, `audit`, `ops`, multi-region), private DNS zone, DR bucket + backup copies in the DR region, PITR lag alarms |
| `infra/terraform/cells/in` | India cell: Mumbai `ap-south-1`, DR Hyderabad `ap-south-2`; one state per environment (`backend-<env>.hcl`, `<env>.tfvars`) |
| `infra/terraform/bootstrap/aws` | Account baseline: encrypted, versioned state bucket + DynamoDB lock table, GitHub OIDC provider, `plan` (read-only, any ref) and `apply` (GitHub environments `infra-staging` / `infra-prod` only) roles |
| `infra/terraform/policy` | conftest (OPA) rules on the plan JSON: required tags, no public DB, encrypted 35-day PITR + deletion protection, full public-access block on every bucket, no internet ingress, no internet gateway |
| `infra/terraform/check-terraform.py` | Offline static rules on the source (tags, static credentials, hard-coded regions, DB/bucket safety), with `--selftest` |
| `.github/workflows/infra.yml` | `static` (always) and `plan-in` (OIDC, once `vars.AWS_PLAN_ROLE_ARN` is set) |

## Local checks (no cloud account)
```
cd infra/terraform
python3 check-terraform.py && python3 check-terraform.py --selftest
tofu fmt -recursive -check
(cd cells/in && tofu init -backend=false && tofu validate)
(cd modules/cell && tofu init -backend=false && tofu test)     # plan-only, mocked providers, second region (AE)
tflint --init --config "$PWD/.tflint.hcl" && tflint --recursive --config "$PWD/.tflint.hcl"
conftest test --policy policy policy/fixtures/plan-good.json   # passes; plan-bad.json must fail
```
`modules/cell` cannot be `tofu validate`d on its own (it needs the `aws.dr` alias from a caller); `cells/in` and the test cover it.

## First apply (Needs external action, once DEC-04 picks AWS)
1. With SSO admin credentials: `cd bootstrap/aws && tofu init && tofu apply -var github_repo=<owner>/<repo>`, then move its state into the new bucket (`tofu init -migrate-state` after adding a backend block).
2. Put `ACCOUNT_ID` into `cells/in/backend-*.hcl`; set repo variables `AWS_PLAN_ROLE_ARN` / `AWS_APPLY_ROLE_ARN` (ARNs, not secrets); create GitHub environments `infra-staging` and `infra-prod` with required reviewers.
3. `cd cells/in && tofu init -backend-config=backend-staging.hcl && tofu plan -var-file=staging.tfvars`, review, apply.

No cloud keys are ever stored: CI uses OIDC, people use SSO. The DB master password is generated by RDS into Secrets Manager.

## Not in this skeleton
NAT / VPC endpoints and the container cluster (DEC-21), Redis-compatible store (DEC-19), public DNS, VPC flow logs and CloudTrail to the audit bucket (CERT-In log story), a cross-region DB read replica (DR placeholder output only), per-tenant DEKs.

Postgres sizing, PgBouncer (transaction mode, 2 instances), the direct endpoint for the relay, the Comms/Edge databases and the pool alarms are described in `docs/runbooks/data-tier.md`. The cell module exports them as output `data_tier`.
