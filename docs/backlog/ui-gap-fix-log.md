# UI gap fixes - branch `fix/ui-gaps`

Frontend-only. 103 "Ready now" items worked: statuses below mirror the backlog (`In review` = implemented, needs browser QA as that role; `In progress` = partly done; `Open` = not done).

Verified here: `tsc`, eslint (no new findings; the pre-existing platform/fleet error is fixed), `npm run check:permissions`, production build, and a headless-browser smoke run of every role's pages against a mock API (no crashes). NOT verified: behaviour against the real backend and per-role QA on the live tenant.

## Needs a decision or confirmation

- Vitals limits (NUR-023, clinical-safety): the backend enforces no range on write; client-side hard limits and the 36.0-37.8 C soft flag are our constants. Clinical review needed.
- Nurses without `patients:view` see no allergy chips (worklist reads `GET /patients/{id}`). Confirm the nurse role grants it, or add a clinical-endpoint fallback.
- Guardian revoke (`PATCH /patients/{id}`) replaces the whole record and wipes address/nationalId - backend needs a partial update. Pre-existing; untouched.
- Phone reveal is a UI policy only (gated on `patients:create`); the server does not mask or audit it.
- Platform permissions for write actions are enforced from role codes (super_admin, billing); confirm against the Roles sheet.
- Pharmacy item activate/deactivate removed: the PATCH API has no `active` field.
- Pharmacy stock +/- sends the whole item (not safe under concurrent edits); a delta endpoint would be safer.
- Setup 'Start import job' posts a placeholder fileName and uploads nothing (API only records a row).
- Money display: INR shows paise only when non-integer.
